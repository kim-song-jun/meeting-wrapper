# MolRoom 디자인·PR 개선 검토

- 기준일: 2026-07-28
- 범위: `main`의 화면 구조, 디자인 시스템 적용 상태, PR 검증 체계
- 목표: Toss처럼 친근하고 명확하되, 기존 MolRoom의 흰 면·Weak 파랑·평면 레이어링을 유지

## 결론

현재 저장소는 이미 `DESIGN.md`와 `tokens.css`를 중심으로 Toss 파생 디자인을 상당히 일관되게 적용하고 있다. 따라서 색상이나 곡률을 다시 갈아엎는 것보다, **좁은 화면의 정보 구조**와 **변경을 검증하는 PR 절차**를 보강하는 편이 효과가 크다.

이번 변경은 다음 세 가지에 집중한다.

1. 모바일 상단 바에서 화면 이동을 분리해 브랜드·계정과 경쟁하지 않게 한다.
2. 태블릿 상단 내비게이션의 선택 상태를 Weak 배경으로 명확히 한다.
3. 모든 PR에서 화면 폭·키보드·safe area·디자인 토큰·자동 검증을 확인하게 한다.
4. 핵심 라우트를 정적 HTML과 고정 크기 PNG로 남겨 리뷰 기준을 눈에 보이게 한다.

## 이번 변경

### 1. 모바일 하단 주요 내비게이션

`<768px`에서는 상단 바에 MolRoom 브랜드와 로그아웃만 남기고, `예약 현황`과 `내 예약`을 고정 하단 바로 옮긴다.

- 흰 면 + 위쪽 1px 경계선만 사용
- 활성 항목은 기존 Weak 쌍(`--c-action-weak-bg`, `--c-action-weak-fg`) 사용
- 모바일 컨트롤 높이 토큰(`--h-action`) 사용
- iOS safe area를 패딩과 본문 하단 여백에 반영
- 다이얼로그보다 낮고 일반 콘텐츠보다 높은 `z-index: 20`
- `prefers-reduced-motion`에서 눌림 변형 제거
- 별도 아이콘·색·그림자·blur를 추가하지 않음

### 2. 태블릿 내비게이션 선택 상태

사이드바가 접히는 `768~1023px` 구간에서 텍스트 링크를 40px 선택 행으로 정리한다. 활성 화면은 Weak 배경으로 표시하고, hover와 focus-visible을 기존 토큰으로 통일한다. 긴 이름·이메일은 이 구간에서 숨겨 화면 이동과 경쟁하지 않게 한다.

### 3. PR 품질 게이트

다음 파일을 추가한다.

- `.github/pull_request_template.md`
  - 1440 / 1024 / 390 / 320px 확인표
  - 키보드·포커스·오버플로·safe area·reduced motion 체크
  - 디자인 토큰과 `local` 근거 체크
  - typecheck / test / build 체크
- `.github/workflows/ci.yml`
  - `npm ci`
  - `npm run typecheck`
  - `npm test`
  - `npm run build`
  - 최소 권한(`contents: read`)과 중복 실행 취소

## 페이지별 HTML·스크린샷 기준 화면

`docs/design-examples/`에 실제 라우트와 핵심 상태를 정적 HTML로 추가한다. 이 파일들은 제품 코드를 대신하지 않고, PR에서 정보 구조·카피·밀도를 빠르게 비교하기 위한 검수 기준이다.

| 화면 | HTML | 스크린샷 | 검수 초점 |
|---|---|---|---|
| 로그인 | `login.html` | `login-mobile.png` · 390×844 | 핵심 행동 하나, 회사 계정 범위, 신뢰 문구 |
| 예약 현황 | `calendar.html` | `calendar-desktop.png` · 1440×1000 | 날짜 제목 우선순위, 가용성 패턴, 사이드바 밀도 |
| QR 회의실 | `room.html` | `room-mobile.png` · 390×844 | 현재 사용 가능 여부와 즉시 예약 종료 시각 |
| 내 예약 | `my-bookings.html` | `my-bookings-mobile.png` · 390×844 | 체크인·취소·비활성 사유와 하단 내비게이션 |
| 예약 다이얼로그 | `booking-dialog.html` | `booking-dialog-desktop.png` · 1440×1000 | 회의실·시간 맥락, 입력 계층, 결과형 버튼 문구 |

공통 원칙은 다음과 같다.

- 외부 폰트·CDN·JavaScript 프레임워크에 의존하지 않는다.
- 로고 이외의 유채색은 Toss 파랑과 상태색만 사용한다.
- 다이얼로그를 제외하고 그림자를 사용하지 않는다.
- 제품에 없는 별도 대시보드·통계·장식 카드를 발명하지 않는다.
- 화면 예시와 실제 구현의 의도적 차이는 PR 본문에 기록한다.
- `node scripts/validate-design-examples.mjs`가 HTML 존재, 외부 의존성 부재, PNG 규격과 갤러리 링크를 검증한다.

| 우선순위 | 관찰 | 제안 | 완료 조건 |
|---|---|---|---|

| P2 | Apple/macOS 판본의 설명이 일부 코드 주석에 남아 현재 Toss 원칙과 혼재한다 | 동작 근거는 남기고 폐기된 재질·플랫폼 서술 제거 | 현재 디자인 언어와 모순되는 `glass`, `vibrancy`, `macOS 얼굴` 주석이 없음 |

## PR 리뷰 순서

1. 사용자가 처음 보는 변화와 핵심 경로를 확인한다.
2. 390px와 320px에서 고정 UI·가로 오버플로·줄바꿈을 본다.
3. 키보드와 focus-visible로 같은 경로를 완료한다.
4. 실패·비활성 상태가 원인과 다음 행동을 말하는지 본다.
5. 새 값이 기존 토큰인지, 새 `local`이면 근거가 있는지 확인한다.
6. typecheck, test, build 결과를 확인한다.
