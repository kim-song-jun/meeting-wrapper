# MolRoom Open Design 선별 흡수 설계

**작성일:** 2026-08-16  
**상태:** B 방향 승인 완료, 구현 전 명세 검토  
**근거:** Local Codex의 최신 Open Design `Web Prototype`과 현재 MolRoom 구현 비교

## 1. 결정

Open Design 시안을 그대로 복제하지 않고, 아래 세 요소만 현재 MolRoom에 흡수한다.

1. 모든 회의실의 현재 상태와 다음 예약을 비교하는 `/rooms` 빠른 예약 허브
2. `예약 현황 · 회의실 · 내 예약`의 3갈래 내비게이션
3. 주요 화면의 제목, 설명, 주 액션을 분명하게 나누는 페이지 위계

현재 제품의 예약 기능과 `DESIGN.md`의 Toss 파생 시각 체계는 유지한다. Open Design의 임시 `MR` 로고, 작은 글자, 다중 그림자, 반투명 표면, 실제 저장소 계약이 없는 취소 되돌리기는 이식하지 않는다.

## 2. 사용자 목표

### 즉석에서 방을 잡는 사람

앱을 열고 한 화면에서 어느 방이 지금 비었는지 비교한 뒤, 가능한 시간을 골라 기존 예약 창으로 이어진다. 방마다 QR을 찾아 들어갈 필요가 없다.

### 미리 일정을 잡는 사람

기존 예약 현황에서 일·목록·주·월 보기를 그대로 사용한다. 새 허브 때문에 격자 기능이나 밀도가 줄지 않는다.

### 내 예약을 관리하는 사람

내 예약 화면에서 체크인, 연장, 취소, 지난 회의 요약, 설정을 그대로 사용한다. 상단의 `새 예약`은 `/rooms`로 이동한다.

## 3. 정보 구조

인증 후 셸의 주요 경로는 다음과 같다.

| 경로 | 이름 | 역할 |
|---|---|---|
| `/` | 예약 현황 | 빈 시간 비교와 정밀 예약 |
| `/rooms` | 회의실 | 지금 가능한 방 비교와 빠른 예약 시작 |
| `/me` | 내 예약 | 예약 관리, 지난 회의, 설정, 관리자 기능 |
| `/r/:roomId` | 방 QR | 특정 방 앞에서 두 번 탭으로 예약 |
| `/login` | 로그인 | 사내 Google 계정 로그인 |

`/rooms`는 `/r/:roomId`를 대체하지 않는다. 전자는 여러 방 비교용이고, 후자는 문 앞에서 이미 방이 정해진 상황용이다.

## 4. 3갈래 내비게이션

표시 순서는 모든 화면 크기에서 `예약 현황 · 회의실 · 내 예약`으로 고정한다.

- `>=1024px`: 기존 사이드바 내비게이션에 `회의실` 행을 추가한다.
- `768~1023px`: 기존 상단 내비게이션에 같은 세 경로를 표시한다.
- `<768px`: 하단 내비게이션을 3등분한다. 각 항목은 44px 이상의 터치 영역을 유지한다.
- 현재 경로는 Weak 쌍(`#E8F3FF` + `#1B64DA`)과 텍스트 굵기로 표시한다.
- 새 아이콘 체계를 발명하지 않는다. 현재 내비게이션의 텍스트 중심 표현을 유지한다.

회의실 표시 토글은 계속 사이드바의 별도 섹션에 둔다. `/rooms`는 격자에 보일 방을 고르는 설정 화면이 아니다.

## 5. `/rooms` 빠른 예약 허브

### 페이지 머리

- 제목: `어느 방을 사용할까요?`
- 설명: `지금 상태와 다음 예약을 비교하고, 가능한 시간을 골라보세요.`
- 보조 이동: `전체 일정 보기` 링크로 `/` 이동
- 제목과 설명은 기존 타입 토큰을 재사용한다. Open Design의 40px 제목이나 새 타입 토큰은 도입하지 않는다.

### 방 카드

각 카드에는 다음 정보만 표시한다.

1. 회의실 이름과 층
2. `지금 비어 있어요`, `지금 사용 중이에요`, `내 회의가 진행 중이에요` 중 하나
3. 다음 예약 시각 또는 `오늘 남은 시간은 모두 비어 있어요.`
4. 현재부터 예약 가능한 시간 선택
5. `이 시간 예약하기` Weak 액션
6. 오늘의 예약 구간을 시간 텍스트 목록으로 표시

회의 제목은 표시하지 않는다. 다른 사람 예약은 주최자 이름도 허브에서 노출하지 않는다. 이 화면의 목적은 방 비교이지 일정 상세 열람이 아니다.

카드는 흰 면, `#E5E8EB` 1px 경계선, 16px 곡률로 만든다. 그림자와 반투명 표면은 사용하지 않는다. 여러 카드에 solid Primary 버튼을 반복하지 않고, 예약 액션은 모두 Weak 버튼으로 통일한다.

### 가능한 시간

현재 시각부터 다음 예약 또는 업무 시간 종료까지의 빈 구간을 계산한다.

- 30분이 가능하면 `30분`
- 60분이 가능하면 `1시간`
- 다음 예약 전까지 30분 초과의 비정형 구간이 있으면 `{HH:mm}까지`
- 이미 진행 중인 예약이 있으면 새 예약 선택을 막고 종료 시각과 다음 행동을 설명한다.
- 정책의 최소 단위, 최대 예약 시간, 업무 시간 범위를 넘는 선택지는 만들지 않는다.

선택 후 바로 저장하지 않는다. 기존 `BookingDialog`를 선택한 방과 시간으로 열어 제목, 인원, 참석자, 반복, Google Meet 등 현재 기능을 그대로 사용한다.

## 6. 데이터 흐름과 경계

### 순수 계산

새 `roomAvailability` 도메인 모듈이 방 하나의 예약 목록과 현재 시각을 받아 다음 정보를 계산한다.

- 현재 예약 상태
- 다음 예약
- 현재 빈 구간 종료
- 표시할 빠른 예약 선택지

React, 저장소, 브라우저 API에 의존하지 않는다. 기존 `currentBooking`, `nextGap`, `hhmm`, 정책 값을 재사용하고 중복 시간 계산을 만들지 않는다.

### 화면 데이터

`RoomsScreen`은 오늘의 전체 예약을 `repo.listByDay(today)`로 한 번 불러온 뒤 방별로 나눈다. 카드마다 저장소를 따로 호출하지 않는다.

- 이전 데이터가 있으면 새로고침 중에도 유지한다.
- 최초 로딩은 화면 상태로 안내한다.
- 최초 실패는 원인과 `다시 불러오기`를 표시한다.
- 갱신 실패는 기존 데이터를 유지하면서 오래된 정보일 수 있음을 알린다.
- 예약 완료 후 목록을 다시 불러와 카드 상태를 갱신한다.

### 예약 창

`RoomsScreen`이 선택한 `{ roomId, start, end }`를 지역 상태로 보관하고 기존 `BookingDialog`를 렌더한다. 저장 성공 시 창을 닫고 오늘 예약을 다시 불러온다. 별도의 빠른 저장 API나 축약 예약 모델을 만들지 않는다.

## 7. 페이지 위계

### 예약 현황

현재 격자 위에 짧은 페이지 머리를 추가한다.

- 제목: `예약 현황`
- 설명: `빈 시간을 골라 예약하고, 내 예약은 바로 바꿀 수 있어요.`
- 보기 전환은 페이지 머리의 오른쪽에 둔다.
- 날짜, 부서, 일·주·월 제어는 기존 툴바에 남긴다.

격자의 시간 밀도, 단일 스크롤러, 방 표시 토글, 드래그 선택·이동·길이 조절은 변경하지 않는다.

### 내 예약

기존 제목 아래에 `다가오는 회의를 확인하고 변경하거나 취소할 수 있어요.`를 표시한다. 페이지 머리의 `새 예약` 액션은 `/rooms`로 이동한다. 탭과 예약 카드의 기능은 변경하지 않는다.

### 모바일

페이지 머리는 제목과 설명을 한 열로 배치한다. 설명 때문에 첫 행동이 화면 아래로 과도하게 밀리면 설명을 숨기지 않고 한 문장으로 유지한다. QR 랜딩은 이번 페이지 위계 변경 대상이 아니다.

## 8. 반드시 보존할 기능

다음 기능의 동작, 데이터 계약, 접근 경로를 제거하거나 축소하지 않는다.

- 일간 격자, 일정 목록, 주간, 월간 보기
- 회의실 표시 토글과 마지막 방 비활성 사유
- 마우스 드래그 예약, 예약 이동, 길이 조절
- 키보드 예약과 포커스 복원
- 방 QR 랜딩의 30분·1시간·다음 예약 전까지 예약
- 체크인, 15분 연장, 회의 종료
- 반복 예약과 부분 성공 결과
- 참석자 초대, 인원, Google Meet, 기본 Zoom 링크
- 내 예약, 지난 예약, 전체 예약, 설정 탭
- 관리자 취소
- 지난 회의 요약 저장, Markdown 복사, Notion 새 페이지 열기
- 현재 로딩·오류·빈 상태와 사용자 안내

## 9. 의도적으로 제외하는 것

- Open Design의 임시 `MR` 로고
- glassmorphism, blur, 다중 그림자
- 11~13px의 주요 인터페이스 글자
- 방의 성격을 설명하는 근거 없는 문구
- 예약 기능 축소나 기존 경로 제거
- 취소 후 `되돌리기`

취소는 Google Calendar 참석자에게 알림을 보낼 수 있는 외부 효과다. 현재 `BookingRepository`에는 취소를 원자적으로 되돌리는 계약이 없으므로, 프로토타입의 메모리 배열 복원 동작을 제품 기능으로 옮기지 않는다.

## 10. 접근성과 상호작용

- 새 내비게이션은 현재 경로를 시각적 스타일과 `aria-current`로 함께 표시한다.
- 방 상태 변경과 예약 완료는 읽을 수 있는 상태 메시지로 알린다.
- 카드의 시간 선택 컨트롤에는 회의실 이름을 포함한 레이블을 제공한다.
- 비활성 액션은 opacity만 낮추지 않고 이유를 상시 표시한다.
- 모바일 터치 타깃은 44px 이상이다.
- 키보드만으로 `/rooms` 진입, 시간 선택, 예약 창 열기, 닫기, 포커스 복귀가 가능해야 한다.
- `prefers-reduced-motion`에서는 이동과 스케일 애니메이션을 제거한다.

## 11. 구현 경계

예상 변경 파일은 다음과 같다.

- `src/App.tsx`: `/rooms` 경로와 3갈래 내비게이션
- `src/screens/RoomsScreen.tsx`: 빠른 예약 허브
- `src/domain/roomAvailability.ts`: 방 상태와 선택지 순수 계산
- `src/domain/roomAvailability.test.ts`: 새 계산 계약
- `src/styles/rooms.css`: 허브 전용 스타일
- `src/styles/navigation.css`: 3갈래 반응형 내비게이션
- `src/screens/GridScreen.tsx`: 예약 현황 페이지 머리
- `src/screens/MyBookingsScreen.tsx`: 설명과 `새 예약` 이동
- `src/styles/screens.css`, `src/styles/mine.css`: 페이지 위계와 반응형 배치

현재 다른 세션 변경이 있는 `src/components/ui.tsx`, `src/screens/BookingDialog.tsx`, `src/styles/components.css`, `src/styles/grid.css`, `src/styles/tokens.css`는 직접 수정하지 않는다. 기존 공개 컴포넌트와 토큰만 사용한다.

## 12. 검증 기준

### 자동 검증

1. `roomAvailability` 테스트를 먼저 실패시키고 구현 후 통과시킨다.
2. 새 경로와 도메인 타입이 TypeScript strict 설정에서 통과한다.
3. 커밋본 기준 빌드에서 누락된 import와 경로가 없어야 한다.

### 실제 화면 검증

호스트 상태를 확인한 뒤 최소 프로세스로 앱을 실행하고 다음을 캡처한다.

- 1440×1000: 예약 현황, 회의실 허브, 내 예약
- 390×844: 3갈래 하단 내비게이션, 회의실 허브, 예약 창
- 핵심 흐름: `/rooms` 진입 → 방 선택 → 시간 선택 → 예약 창 → 예약 완료 → 카드 갱신
- 키보드 흐름: 내비게이션 → 시간 선택 → 예약 창 → 닫기 → 원래 컨트롤 포커스 복귀

Open Design 캡처와 구현 캡처를 같은 QA 단계에서 확인하되, 시안과의 차이가 `DESIGN.md` 준수 또는 기존 기능 보존 때문인지 기록한다. 그림자·유리·임시 로고·작은 글자가 다시 들어오면 실패다.

## 13. 완료 조건

다음이 모두 참일 때 완료다.

1. `/rooms`가 실제 저장소 데이터로 모든 방의 현재 상태와 빠른 예약 선택지를 보여준다.
2. 데스크톱·태블릿·모바일에서 3갈래 내비게이션이 동작한다.
3. 예약 현황과 내 예약의 페이지 위계가 명확해진다.
4. `/rooms`에서 기존 `BookingDialog`를 통해 예약을 만들 수 있다.
5. §8의 기존 기능이 제거되거나 막히지 않는다.
6. 새 도메인 테스트, 타입 검사, 빌드, 실제 화면 QA가 각각 근거를 남긴다.
7. 이번 작업이 시작하기 전 존재한 타 세션 변경을 덮어쓰거나 커밋하지 않는다.
